## 一、项目概述

基于开源项目 **Pi** 进行二次开发，构建一款同时适配 Windows 和 macOS 的桌面端 AI Agent 软件，内置市面上主流 Agent 常见的核心能力，包括 Skills、MCP（Model Context Protocol）、自定义全局约束等，支持灵活添加、切换符合 OpenAI 协议的自定义大模型（通过 APIKey 配置），并具备便捷的全局快捷键唤起、系统托盘驻留等桌面端交互能力。

整体设计遵循 **高内聚、低耦合、可扩展、可维护** 的最佳实践原则，优先完成整体架构搭建，再逐步实现具体功能；AI 能力部分复用 Pi 开源项目的既有能力作为底层引擎。

## 三、功能需求详述

### 1. 全局快捷键唤起

**功能描述：**

- 默认快捷键：`Ctrl + Shift + 0`（Windows）
- macOS 默认可使用 `Cmd + Shift + 0`（或进入设置后可自定义）
- 首次按下：呼出软件主窗口，若当前无活动对话则自动新建一个对话
- 再次按下：隐藏主窗口（后台驻留）
- 快捷键需支持在设置页中自定义修改并即时生效

### 2. 系统托盘功能（Windows / macOS）

- 点击窗口右上角关闭按钮时，**不退出程序**，而是隐藏至系统托盘
- 托盘图标右键菜单包含以下功能：
  - **打开**：重新唤出主窗口
  - **设置**：直接打开设置页面
  - **退出**：完全退出程序

### 3. 主窗口 UI 布局

整体为「极简工具风格」，分为左右两大区域 + 底部状态区。

#### 3.1 左侧 —— 项目与对话历史区

- 顶部区域为「项目区」：
  - 左侧显示标题文字（如「项目」）
  - 标题右侧有 **「+」号图标**，点击后弹出输入框或文件选择器，创建/添加一个新的项目（对应本地文件夹路径）
- 项目下方展示该项目的**对话历史列表**
- 点击历史对话可加载该会话的聊天内容，继续对话

#### 3.2 右侧 —— 聊天区域

- 展示当前对话的聊天消息流（用户消息 / AI 回复）
- 支持消息的流式输出显示（同 Pi 项目效果）
- 支持复制、重新生成等基础消息操作

#### 3.3 底部输入区域

- **大输入框**：支持多行输入，可**垂直拖拽调整高度**
- **Slash 命令唤起 Skills**：
  - 在输入框中输入 `/` 时，输入框上方弹出 Skill 候选列表
  - 支持键盘 **上下方向键** 选择，或通过鼠标点击选择
  - 选定 Skill 后，其名称自动插入输入框，用户可直接输入针对该 Skill 的提示词
- **输入框右下角功能控件**（自左向右）：
  - **模型选择器**：下拉展示当前可用的所有 AI 模型
  - **模型强度/规格选择**：如 temperature、上下文长度、推理强度等（不同模型支持不同强度参数）
  - **发送按钮**：点击后提交对话消息

#### 3.4 左下角设置入口

- 左下角放置 **「设置」按钮**（齿轮图标）
- 点击后打开设置页面

### 4. 设置页面

设置页支持以下配置能力：

- **模型管理**
  - 添加自定义模型（名称、Base URL、API Key、模型标识，需符合 OpenAI 协议）
  - 编辑 / 删除已有模型配置
  - 切换默认使用的模型
- **快捷键设置**
  - 自定义全局唤起快捷键
- **自定义全局约束提示词（Global System Prompt）**
  - 配置作用于所有对话的系统级约束指令，如角色设定、输出风格、行为边界等
- **其他设置**
  - Skills 目录管理（可选）
  - MCP 配置入口（可选）

### 5. 常见能力集成

| 能力                | 说明                                                                                                               |
| ------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **Skills**          | 支持自定义 Skill 定义与调用，输入 `/` 唤起选择，将 Skill 指令注入对话上下文                                        |
| **MCP**             | 支持接入 MCP 协议服务，为 Agent 提供工具调用能力（文件读写、网络访问、第三方 API 等）                              |
| **全局约束**        | 支持全局 System Prompt 约束，所有对话生效                                                                          |
| **OpenAI 协议模型** | 通过 Base URL + APIKey 自由添加任意兼容 OpenAI 协议的大模型服务（如 OpenAI、Anthropic 中转、本地 Ollama、vLLM 等） |

### 6. 窗口基础控制

- 右上角包含标准的 **最小化、最大化/还原、关闭** 三个窗口控制按钮
- 关闭按钮行为为隐藏至托盘（见前述），顶部菜单或设置页可提供「退出」入口

## 四、架构设计原则

采用 **分层 + 模块化 + 插件化** 架构，确保系统满足以下特性：

- **高内聚**：每个模块职责单一，内部实现自治
- **低耦合**：模块之间通过接口通信，避免直接依赖
- **可扩展**：模型接入、Skill、MCP 等均设计为可插拔扩展点
- **可维护**：类型安全、命名规范、目录清晰、日志完善

## 五、目录结构规划（建议）

```
src/
├── main/                 # 主进程（Tauri/Electron 主入口）
│   ├── window/           # 窗口管理（创建、隐藏、显示、托盘联动）
│   ├── tray/             # 系统托盘管理
│   ├── shortcut/         # 全局快捷键注册与处理
│   ├── settings/         # 配置读写与持久化
│   └── ipc/              # IPC 通信处理层
├── core/                 # 核心业务逻辑（框架无关）
│   ├── agent/            # AI Agent 引擎封装（基于 Pi 能力）
│   ├── model/            # 模型管理（OpenAI 协议适配器）
│   ├── skill/            # Skill 加载、解析与执行
│   ├── mcp/              # MCP 连接与工具调用
│   ├── memory/           # 对话历史存储与加载
│   ├── context/          # 全局约束/上下文管理
│   └── events/           # 事件总线（模块间解耦通信）
├── renderer/             # 渲染进程（UI 层）
│   ├── components/       # 通用组件（输入框、消息列表、窗口按钮）
│   ├── pages/            # 页面（主聊天页、设置页）
│   ├── stores/           # 全局状态管理
│   ├── styles/           # 样式定义
│   └── utils/            # 前端工具函数
├── shared/               # 主进程与渲染进程共享类型与常量
│   ├── types/            # 共享类型定义
│   └── constants/        # 常量定义（默认快捷键等）
└── pi/                   # Pi 开源项目核心代码（或作为外部依赖引入）
```

## 六、核心模块设计描述

### 1. Agent 引擎模块

- 对 Pi 的核心 Agent 能力进行二次封装，向上暴露统一接口（发送消息、流式输出、中断响应等）
- 设计 `AgentEngine` 抽象接口，使底层可替换为其他 Agent 实现而不影响上层业务
- 内部集成 Skills 与 MCP 工具调用能力，根据用户输入自动触发对应工具

### 2. 模型管理模块

- 新增模型需配置：
  - 模型显示名称
  - Base URL（需符合 OpenAI 协议）
  - API Key
  - 模型标识（如 `gpt-4o`，`qwen-plus` 等）
- 所有模型配置通过本地配置持久化保存
- 通过统一的 OpenAI 兼容适配器与各模型服务通信

### 3. Skills 模块

- 每个 Skill 包含：名称、描述、触发指令、提示词模板、所需参数
- Skill 定义可存放于本地目录，启动时加载并索引
- 通过在输入框输入 `/` 唤起 Skill 列表选择，将对应 Skill 内容注入当前对话上下文

### 4. MCP 模块

- 支持配置多个 MCP Server（HTTP/STDIO 协议）
- Agent 运行时可调用 MCP 暴露的工具，扩展 Agent 的外部世界操作能力

### 5. 事件总线

- 模块之间不直接互相调用，统一通过事件总线发布/订阅模式通信
- 如：托盘点击「打开」→ 发布 `window-open` 事件 → 窗口管理模块响应显示窗口

## 七、实施步骤建议

1. **初始化项目架构**
   - 引入 Tauri/Electron + 前端框架，搭建主进程与渲染进程骨架

   - 系统托盘集成与右键菜单
   - 全局快捷键注册与响应

   - 左右布局 + 底部输入框
   - 对话消息展示与流式输出
   - 输入框高度可调

4. **接入 Pi Agent 能力**
   - 封装 Pi 核心为 Agent 引擎
   - 对话可正常调用模型并流式返回结果

5. **实现模型管理**
   - 自定义模型添加 / 编辑 / 删除

6. **实现项目与对话历史**

   - 历史对话的加载与继续

7. **实现 Skills 功能**
   - Skill 定义与解析
   - `/` 唤起 UI 与选择交互

8. **实现 MCP 能力**
   - MCP 配置管理
   - 工具调用链路打通

9. **实现全局约束设置**
   - 设置页全局约束指令配置
   - 对话注入约束系统指令

10. **完善设置页与整体打磨**
    - 快捷键自定义
    - UI 细节与极简风格打磨
    - 多平台打包与测试

## 八、注意事项

- **Mac 平台权限**：全局快捷键与托盘在 macOS 上需注意辅助功能权限与通知权限适配
- **窗口隐藏策略**：macOS 下关闭按钮默认行为建议与平台习惯保持一致，但需确保不直接退出进程
- **数据安全**：API Key 等敏感信息本地加密存储
- **Pi 依赖管理**：若 Pi 项目持续更新，尽量保持基于其公开接口的封装，降低升级成本
